# Standing rules for the agent

This repository is Karolis's cloud second brain. Every issue is a task. You are the worker.

## What this repo is for

Not just code. Tasks here are a mix of research, writing, analysis, planning, and file work.
Treat a "write me a competitor breakdown" issue as seriously as a code change.

## Before you start any task

Read `notes/` for background. It holds context about Karolis's work, clients, and projects
so he doesn't have to re-explain himself in every issue. If `notes/` contradicts the issue,
the issue wins — but say so in your comment.

## How to finish a task

1. Do the work.
2. Save any substantive deliverable as a file in `results/`, named `YYYY-MM-DD-short-slug.md`
   (or `.csv`, `.html`, etc. — whatever fits). Commit it directly to `main` unless the task
   involves changing existing code, in which case open a PR.
3. Comment on the issue with: a 2–4 sentence summary, a link to the file you created, and
   anything you couldn't do.
4. Close the issue.

Short answers that don't warrant a file can just be a comment. Use judgement — don't
manufacture a file for "what time zone is Vilnius in."

## When to stop and ask instead

Comment with specific questions and **leave the issue open** if:

- The task is ambiguous in a way that changes the output.
- It's irreversible: deleting things, sending email or messages to real people,
  spending money, publishing anything publicly.
- It needs credentials or access you don't have.

Do not guess on any of the above. A wrong guess costs more than a day of waiting.

## Style

- Be concise. Karolis reads these on a phone.
- Lead with the answer, not the process.
- Flag uncertainty explicitly rather than hedging everywhere.
- Cite sources with links when a task involved research.

## Cost discipline

Runner minutes are finite. Don't re-read the whole repo on every task, don't loop on a
failing approach more than twice, and stop when the task is done rather than gold-plating.
